# 기업 맥락 꼬리질문

## 처리 흐름

기업 선택 면접의 꼬리질문을 두 단계로 처리한다.

1. **A 일반 판단**: 기존 기업 없는 프롬프트와 모델 파라미터로 점수·필요 여부·일반 질문 후보를 만든다.
2. **B 기업 생성**: A에서 질문이 필요하고 기업 정보와 남은 시간이 있을 때만 한 번 더 호출한다.
   원질문·의도·참고 답안·실제 답변·면접관 설정·일반 후보·기업 이름·요약을 사용한다.
3. B가 성공하면 새 응답에 A의 `score`·`required`와 B의 질문 필드 네 개를 조합한다.
   B가 실패하면 A의 일반 질문 전체를 그대로 반환한다. A 오류는 기존 `notRequired` 정책을 따른다.

기업을 선택하지 않은 면접은 모델 호출 한 번과 기존 프롬프트를 유지한다.
실제 질문·답변 본문에 있는 기업 이름은 삭제하지 않는다. 별도로 주입하는 기업 맥락만 A에서 제외한다.
B 입력에는 점수·필요 여부·질문 ID를 넣지 않는다.

## 입력과 응답 계약

준비 요청의 `company`에는 기존 `displayName`과 `interviewerBrief`만 받는다.
앞뒤 공백을 제거한 뒤 Unicode code point 기준 각각 1~30자·1~600자를 검사한다.
company 생략·null은 일반 면접이며 빈 객체나 일부 필드 누락은 검증 오류다.
Redis 스냅샷·준비 재전송 멱등성·기존 company 없는 세션 호환은 기존 경로를 사용한다.
기업 DB·외부 URL·facts 조회를 추가하지 않는다.

B 응답은 `intention`, `content`, `spokenText`, `expectedAnswer` 네 필드만 허용한다.

- intention·content: 공백뿐인 값 금지, 각각 최대 200자
- expectedAnswer: 공백뿐인 값 금지, 최대 1,000자
- spokenText: null 또는 최대 1,000자. 공백뿐이면 null로 정규화해 기존 TTS 대체 규칙 사용
- 길이는 앞뒤 공백 제거 후 Unicode code point 수로 계산
- 알 수 없는 필드·잘못된 타입·중복 키·뒤에 붙은 JSON·코드 펜스·빈 본문·상한 초과는 거부
- `stop_reason=end_turn`이고 텍스트 블록 한 개일 때만 채택. 잘린 결과는 부분 채택하지 않음

질문 ID·부모 관계·면접관 배정·첫 꼬리질문 -1 규칙·WebSocket·TTS 경로는 기존 서비스가 담당한다.

## 설정과 활성화

| 환경 변수 | 기본값 | 용도 |
|---|---|---|
| ANTHROPIC_COMPANY_FOLLOW_UP_ENABLED | false | B 기업 생성 활성화 |
| ANTHROPIC_COMPANY_FOLLOW_UP_TOTAL_TIMEOUT | 5s | 기업 면접 A+B 전체 시간 예산 |
| ANTHROPIC_COMPANY_FOLLOW_UP_GENERATION_TIMEOUT | 2s | B 시간 상한 |
| ANTHROPIC_COMPANY_FOLLOW_UP_MAX_TOKENS | 800 | B 출력 토큰 상한 |

시간과 토큰 값은 양수여야 한다. B에는 생성 상한과 전체 남은 시간 중 작은 값을 적용한다.
전체 시간은 구독 시점부터 A의 연결 대기·응답과 B를 포함한다.
기업 없는 요청은 기존 네트워크 시간 제한을 유지한다.
flag=false인 기업 면접도 A 일반 경로를 사용하며 기업 정보를 다시 A에 넣지 않는다.

A/B는 기존 동시성 슬롯 하나를 공유하며 순차 실행한다. 재시도는 추가하지 않는다.
B의 오류·429·시간 초과는 A로 복귀한다. 사용자 요청 취소는 네트워크로 전파하며
결과를 반환하거나 늦은 질문을 저장하지 않고 슬롯을 반환한다.

활성화 전 선별 실제 모델 출력으로 원질문 의도·핵심 답변 범위 유지, 기업 내부 사정의 창작 여부,
회사 소속 발화, spokenText 의미 보존을 검수한다. 형식 검증만으로 의미 품질을 보장하지 않는다.
최대 두 번의 모델 호출이 발생하므로 비용·기업 적용률·fallback 비율·p95 지연을 측정한 뒤 활성화한다.
이번 자동 테스트는 실제 유료 모델을 호출하지 않으며 실제 모델 품질·부하 측정은 별도다.

## 관측과 검증

신규 `follow_up.call` 로그는 phase A/B, 상태, stop_reason, 지연, 입력·출력 토큰,
call_count를 기록한다. 응답 envelope가 없으면 토큰은 0(실제 사용량 미확인)이다.
`follow_up.company`는 applied 또는 fallback과 사유 코드를 기록한다.
질문·답변·기업 요약·모델 응답 원문은 신규 로그에 넣지 않는다.
기존 Anthropic 요청 메트릭은 A+B 논리 요청 단위이며 단계별 실제 시도 수는 call 로그로 구분한다.

Java 21과 redis-server가 있는 환경에서 `./gradlew test`를 실행한다.
가짜 WebClient와 가상 시계로 호출 분기·엄격 스키마·폴백·시간 예산·취소·슬롯 반환을 검증한다.
기존 프롬프트 골든·준비 요청·Redis·질문 ID·부모 관계·TTS 테스트도 함께 실행한다.
